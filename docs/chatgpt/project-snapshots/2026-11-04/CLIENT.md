# Addons, macros, UI and client troubleshooting

- Identify the actual client/version, OS, addon release and observed symptom. Check maintainer instructions and current compatibility before recommending an addon. Loading successfully does not prove a particular feature works.
- For macros, supply the smallest usable code first, then explain constraints. Verify exact spell/item names, rank, conditional syntax, targeting, action-per-click, global cooldown, secure action restrictions, sequence reset and client compatibility. Do not promise automated decisions or several GCD actions from one click.
- Prefer native UI settings when adequate. For broken addon or client behaviour, isolate variables and use reversible tests. Back up profiles, Edit Mode, keybindings, WTF and SavedVariables before destructive changes; avoid generic full resets.
- Preserve imported/exported client data and verify formats, scope and target account/client. Do not execute uploaded Lua. Source files may contain information unsuitable for public Tazdingo submission; inspect intended publication scope before sending.
- For known bugs or frequently updated addons, use current maintainer and user reports; an older Tazdingo workaround is a dated observation, not automatically a current fix.
